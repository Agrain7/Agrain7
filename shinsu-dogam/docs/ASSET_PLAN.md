## 2. 교체 우선순위 (예산 20~40만 원 범위에서)
1. **라이더 하람** — 영물 원화와 화풍 통일이 가장 눈에 띈다. 프레임: 앉기 4, 몸 숙이기 4, 손 뻗기 2, 피격 1, 환호 2
2. **월하산맥 배경 레이어** — 원경·중경·근경·전경 분리 제작
3. **몬스터 5종 + 보스** — 걷기 6, 공격 6, 피격 1
4. **영물 프레임 애니메이션** — 늑대 → 매 → 청룡 순, 단계별 달리기 8·대기 6·점프 2·공격 5·비행 6 (같은 디자인 유지가 핵심)
5. 배경음악 2곡(필드·보스) + 효과음 20종

## 3. 교체 방법 (코드 수정 최소화)
- 영물: 같은 파일명(`<id>_<stage>.png`)으로 덮어쓰고 `src/data/mountArt.ts` 의 `w·h·seat` 갱신 → 자동으로 애니메이션 변형 적용
- 프레임별 원화가 생기면: 스프라이트 시트(프레임 크기·원점 통일) + `src/game/textures.ts` 의 `ensureMount` 에서 시트를 그대로 등록하도록 분기 추가 (애니메이션 키 `:idle/:run/:fly` 유지)
- 배경: `src/art/world.ts` 의 각 paint 함수 대신 이미지 로드 (`BootScene.preload`) — 레이어 크기 2048×(260~620), 가로 이음매 없이 타일 가능해야 함
- 몬스터: `textures.ensureMonster` 를 이미지 시트 로드로 교체 (프레임 이름 `idle_0`, `run_0` … 유지)

## 4. 스프라이트 시트 규격
| 항목 | 규격 |
|---|---|
| 방향 | 오른쪽을 바라봄 (왼쪽은 게임에서 반전) |
| 배경 | 투명 PNG |
| 원점 | 발이 닿는 지면 중앙 (모든 프레임 동일 위치) |
| 프레임 크기 | 캐릭터별 고정 (예: 영물 각성체 384×256, 유체 192×160) |
| 해상도 | 게임 표시 크기의 1~1.5배 (게임 기준 해상도 1280×720) |
| 외곽선 | 진한 먹색 2~3px 상당, 원화와 같은 두께감 |
| 파일명 | `<대상>_<단계>_<동작>.png` 또는 시트 + JSON |

## 5. 제작 순서 (원 프롬프트 기준)
늑대 유체 → 늑대 성장체 → 늑대 각성체 → 라이더 → 매 3단계 → 청룡 3단계 → 몬스터 → 보스
(영물은 이미 원화가 있으므로, 프레임 애니메이션 제작 시 이 순서를 따른다)

## 6. 관리 규칙
- 모든 에셋은 [ASSET_MANIFEST.md](ASSET_MANIFEST.md) 에 등록하고, 출처·도구·라이선스는 [ASSET_LICENSES.md](ASSET_LICENSES.md) 에 기록
- AI 도구로 만든 이미지는 생성 도구·플랜·날짜·프롬프트·수정 이력을 남긴다
- 타사 캐릭터·게임 디자인을 모방하지 않는다
